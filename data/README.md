# Data Directory Structure

Nothing in `data/` is git-tracked (see Git Policy below) — this file
documents what's here for anyone (including future-session Claude) working
from a local copy.

## Directory Organization

### `raw/`
Unmodified downloads from `nfl_data_py` / `nflreadpy`.
- `pbp_2015_2025.csv`: play-by-play data (EPA/play, by player/game/position)
- `schedules_2015_2025.csv`: game schedules + real Vegas lines + results, 2015-2025
- `schedules_2026.csv`: 2026 schedule (lines mostly not yet posted this far out)
- `snap_counts_2015_2025.csv`, `defense_pfr_2015_2025.csv`, `player_metadata.csv`, `player_weekly_raw_2015_2025.csv`, `player_seasonal_raw_2015_2025.csv`, `vegas_lines_2015_2025.csv`

### `processed/`
Derived data: features, ratings, predictions. All regeneratable from `raw/` + source code — nothing here is a primary source.

**Two parallel prediction tracks live here** (see root `README.md` for the
full architecture):
- EPA/player pipeline: `team_strength_{season}.csv`, `win_projections_{season}.csv`, `game_predictions_{season}*.csv`, `{qb,rb,wr,te}_epa_projections_{season}.csv`, `{edge,dl,cb,s,lb}_*predictions*.csv`
- Elo pipeline: `elo_ratings_{season}.csv`, `elo_season_wins_{season}.csv`, `elo_game_predictions_{season}.csv`, `elo_game_spreads_{season}.csv`, `weekly_updated_spreads_*.csv`, `vegas_blended_spreads_learned_*.csv`

**`archive/`**: 7 superseded files from the pre-Elo Phase 3 candidate-testing
era (6 `team_strength_2025_*_corrected.csv` variants that lost to the
production formula, plus a pre-SOS-bugfix `optimized_offensive_weights.csv`).
Kept for history, not used by any current code path — PROGRESS.md documents
which formula won and why. Safe to delete outright if disk space matters;
moved here rather than deleted during the 2026-07-27 cleanup on the
"reversible over destructive" principle.

**Naming conventions actually in use**:
- `*_corrected.csv` (outside `archive/`): post-SOS-bugfix version — current, not stale, despite the name looking similar to the archived ones.
- `*_leakfree_*.csv`: predictions built with an explicit leak-free ref_season override.
- `*_{season}.csv` with no other suffix (e.g. `team_strength_2025.csv`): production version for that season.
- `*_after_week{N}.csv` / `_week{N}.csv`: checkpoint snapshots from in-season simulation (Dynamic Tracking, Component B), not separate models.

### `diagnostic/`
Validation outputs and accuracy metrics — nothing here feeds back into a
prediction, these are all read-only evidence for claims made in PROGRESS.md.
E.g. `elo_backtest_2025.csv`, `elo_game_validation_2024.csv`,
`weekly_recalibration_trajectory_2025.csv`, `learned_optimal_weights_loocv.csv`,
`fantasy_validation_2025.csv`.

### `backtest/`
Historical ground truth used across many modules: `game_results_2015_2025.csv`,
`vegas_with_results_2015_2025.csv`, `actual_wins_2025.csv`,
`win_projections_vs_actual_2025.csv`. Not regenerated by the normal pipeline
runs — these are the fixed real-outcome files everything else is checked
against.

### `fantasy/`
Fantasy-specific outputs (`fantasy_validation.py`).
- `actual_fantasy_points_2025_by_week.csv`: real PPR points scored, per player per week (sourced from `processed/player_weekly_stats.csv`, not re-derived from PBP)
- `projected_fantasy_score_2025_{qb,rb,wr,te}.csv`: EPA-based projected scores per position

## Regenerating Data

```bash
python src/data_pipeline.py          # raw -> player-level EPA features
python src/epa_to_wins.py            # EPA pipeline: team strength -> season wins
python src/game_predictions.py       # EPA pipeline: team strength -> game spreads
python src/elo_model.py              # Elo pipeline: ratings + validation
python src/elo_game_prediction.py    # Elo pipeline: ratings -> game spreads
python src/fantasy_validation.py     # fantasy validation outputs
```

Each module's own docstring documents its specific inputs/outputs and any
corrections made to the spec it was built from — check there before assuming
a file's purpose from its name alone.

## Git Policy

**Nothing in `data/` is git-tracked.** Every subdirectory is covered by
`.gitignore` (`data/{raw,processed,backtest,diagnostic,fantasy}/*`, each with
a `.gitkeep` so the empty directory structure itself is preserved). This is
intentional — regenerate locally from `raw/` + source rather than expecting
`git clone` to populate `data/`.
